# sources

`sources/` 负责保存外部资料的阅读分析，包括论文、博客、课程、报告和官方文档。它关注“这份资料本身讲了什么”，不是最终知识结论页。

## 当前模块职责

- 记录资料来源、核心问题、主要贡献、关键证据、局限和个人理解。
- 为主题目录中的知识笔记提供引用来源和阅读依据。
- 区分资料类型，但不把资料笔记和稳定知识归纳混在一起。

## 直接子项

- `index.md` — Sources 网页入口与命名规则。
- `papers/` — 论文阅读分析。
- `blogs/` — 博客、技术文章、访谈和工程经验阅读。
- `courses/` — 课程、讲义、公开课和教学资料笔记。
- `reports/` — 技术报告、行业报告、白皮书和模型报告。
- `docs/` — 官方文档、API 文档、框架文档阅读。

## 契约

- 每篇资料笔记应说明来源、作者或机构、发布时间、核心结论和个人判断。
- 资料笔记不承担完整知识体系归纳；归纳后的稳定知识应回写到对应主题目录。
- 如果资料跨多个主题，保留在对应来源目录中，并在相关主题笔记中建立双链引用。
- 源码阅读、实际复现、实验和工程记录放入 `../projects/`。

## 边界

- 概念解释和知识归纳放入 `../fundamentals/`、`../architecture/`、`../training/`、`../inference/`、`../application/`。
- 自己动手实验、复现和工程记录放入 `../projects/`。
- 本目录按资料类型分二级目录，不再在根目录平铺资料笔记。

## Direct-Call 信息

- 目录入口链接：`[[sources/|Sources]]`。
- 典型引用方式：主题笔记引用资料笔记，例如 `[[sources/papers/2023-dpo|DPO 论文阅读]]`。
- 源码阅读示例：`[[projects/transformers-llama-code-reading|Transformers LLaMA 源码阅读]]`。
