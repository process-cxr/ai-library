# projects

`projects/` 负责保存个人动手实践记录，包括实验复现、Demo、部署记录、评测流程、源码阅读和工程踩坑。它关注“我实际做了什么、读了什么代码以及结果如何”。

## 当前模块职责

- 记录实践目标、环境、步骤、结果、问题和复盘。
- 把阅读资料、源码理解和知识主题落到可验证的实践经验中。
- 为后续复现、迭代和项目展示提供线索。

## 文件

- `index.md` — Projects 网页入口与项目类型说明。
- 其他 `.md` — 单个实验、复现、Demo、源码阅读或工程记录。

## 契约

- 每篇项目笔记应说明目标、输入、操作步骤、输出结果和结论；源码阅读笔记应说明阅读对象、入口文件、核心流程和关键发现。
- 涉及外部资料时，链接到 `../sources/` 中对应阅读分析。
- 沉淀出的稳定概念或方法，应链接或回写到对应主题目录。

## 边界

- 资料阅读分析放入 `../sources/`。
- 稳定知识归纳放入五个主题目录。
- 不作为临时 TODO 或日常进度日志使用。

## Direct-Call 信息

- 目录入口链接：`[[projects/|Projects]]`。
- 典型引用方式：项目笔记引用主题笔记和资料笔记，例如 `[[inference/serving-systems/vllm|vLLM]]`、`[[sources/paper-2022-flashattention|FlashAttention 论文阅读]]`。
